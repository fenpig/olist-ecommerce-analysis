## DEC-001：主延迟口径与分类

- **决策**：主分析的 `delay_days` 使用 `DATE(order_delivered_customer_date) - DATE(order_estimated_delivery_date)`，单位为整数日。
- **分类**：`delay_days <= 0` 为按时或提前；1–3 天为轻微延迟；4–7 天为中度延迟；大于 7 天为严重延迟。
- **保留字段**：同时保留 `delay_hours_raw = order_delivered_customer_date - order_estimated_delivery_date`，仅用于数据审查与补充分析，不得作为主延迟分类依据。
- **适用样本**：`order_status = delivered`，且实际送达、预计送达日期完整且可解析。
- **依据**：预计送达字段的 99,441 个可解析时间值均为 `00:00:00`，表达的是日期而非精确送达时点。

## DEC-002：一单多评的订单级主评分

- **决策**：订单级主评分采用最新的有效评价，不使用多个评分的平均值。
- **排序规则**：先按 `review_answer_timestamp` 降序；若缺失或相同，再按 `review_creation_date` 降序；仍相同则以 `review_id` 为稳定排序字段。
- **异常规则**：若所有排序字段仍无法判定先后且评分冲突，标记为评价冲突订单，保留在质量统计中，但排除在配送时效与评分关系主分析之外。
- **须生成的审计字段**：`review_record_count`、`has_multiple_reviews`、`has_conflicting_review_scores`。
- **敏感性分析**：主分析完成后，以同一订单的最低有效评分作为对照口径，检查核心结果是否有明显变化。

## DEC-003：月度趋势边界月份

- **决策**：2016-09、2016-12、2018-09、2018-10 不进入主要月度趋势、环比或增长率计算。
- **仍须保留**：这些记录继续纳入全量订单数、订单状态、总体履约、数据质量报告和边界月份附录；不得从原始或分析基础数据中删除。
- **验证依据**：每月覆盖天数、每日订单数量和相邻月份差异已记录在 `DATA_QUALITY_REPORT.md`。若后续增量数据推翻该判断，必须先提供证据并再次确认，不得自行调整。

## DEC-004：一期范围与缺失数据

- **卖家分析**：一期仅到 `seller_id`；不得根据 ID 推测卖家所在城市或州。
- **地区分析**：一期仅到客户 `customer_state`。
- **商品分析**：一期仅到商品类别。
- **明确不做**：卖家城市/州分析、客户—卖家距离、物流半径、依赖经纬度的精确地图。
- **数据依赖**：`olist_sellers_dataset.csv` 为高优先级待补充文件，建议在最终项目交付前补齐；`olist_geolocation_dataset.csv` 为二期增强数据。
